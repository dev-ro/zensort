# Fix YouTube Pagination, Auto-Sync Mismatch, and Non-Destructive Errors

## What I Verified vs 007 plan

- Pagination only streams first 100 (`watchLikedVideos`) with no load-more API; BLoC/UI lack `LoadMoreAllVideos` wiring.
- Auto-sync mismatch compares `remoteTotal` to the 100-item page length, causing constant re-syncs.
- Cloud Function is 540s server-side, but client call lacks extended timeout and emits `YoutubeFailure`, clearing shelves.
- Category resolver, denormalized fields, and rules are implemented per plan.

## Changes

### 1) Domain: Pagination cursors (architecture-correct)

- Create `lib/features/youtube/domain/entities/liked_videos_page.dart`:
  - `class LikedVideosPage { List<LikedVideo> videos; String? nextCursor; bool hasMore; }`
- Update `lib/features/youtube/domain/repositories/youtube_repository.dart`:
  - Add:
    ```dart
    Future<LikedVideosPage> fetchLikedVideosPage({String? startAfterId, int limit = 100});
    ```

  - Keep `watchLikedVideos()` for the initial 100 stream.
- Delete or move Firestore-coupled `paginated_videos.dart` out of domain.

### 2) Data: Repository implementation

- In `lib/features/youtube/data/repositories/youtube_repository_impl.dart` add `fetchLikedVideosPage`:
  - Use `orderBy('likedAt', desc).limit(limit)` and `startAfter(startAfterDoc)`.
  - Return `LikedVideosPage` with `nextCursor = lastDoc.id` and `hasMore = docs.length == limit`.

### 3) Presentation/BLoC: Load-more and state

- In `lib/features/youtube/presentation/bloc/youtube_event.dart` add `LoadMoreAllVideos`.
- In `youtube_state.dart` extend `YoutubeLoaded` with:
  - `bool loadingMore`, `bool hasMore`, `String? nextCursor`.
- In `youtube_bloc.dart`:
  - Maintain `lastLoaded` cache.
  - On `_LikedVideosUpdated`, set initial `allVideos` + `hasMore=true` (unknown yet), `nextCursor=null` (will be set after first explicit page fetch) OR immediately compute via a one-shot `fetchLikedVideosPage(startAfterId: lastDocIdOfInitialStream)`.
  - Handle `LoadMoreAllVideos`: guard `loadingMore/hasMore`, call repo `fetchLikedVideosPage(startAfterId: state.nextCursor)`, append videos, update cursor/hasMore, set `loadingMore=false`.
  - Build shelves from aggregated `allVideos`. No empty shelves.

### 4) UI: Auto-infinite scroll on All Videos

- In `home_screen.dart`, when rendering the first shelf (All Videos), pass `hasMore`, `isLoading`, and `onEndReached: () => bloc.add(LoadMoreAllVideos())` to `ExpandableVideoShelf`.
- In `expandable_video_shelf.dart` make the grid scrollable for the All Videos shelf to emit scroll notifications:
  - For All Videos only: set a bounded height (viewport-based) and enable scroll on the inner grid or switch to a `CustomScrollView` with a `SliverGrid` for a smoother single scroll. Keep 70% threshold logic.

### 5) Auto-sync mismatch logic (one-time, aggregate count)

- In `youtube_bloc.dart::_verifyTotalsOnceAsync`:
  - Fetch `localCount = await _youtubeRepository.fetchLocalLikedVideosCount()` (aggregate), not `event.videos.length`.
  - Compare once: only trigger `SyncLikedVideos` if `localCount == 0` OR `(remote - local) >= 5`.

### 6) Sync callable timeout + non-destructive errors

- Client timeout: set 9m on `HttpsCallable` for `sync_youtube_liked_videos` (and keep default for `get_liked_videos_total`).
  ```dart
  final syncCallable = FirebaseFunctions.instance.httpsCallable(
    'sync_youtube_liked_videos',
    options: HttpsCallableOptions(timeout: const Duration(minutes: 9)),
  );
  ```

- In `youtube_bloc.dart` error paths:
  - In `_onSyncLikedVideos` catch: if current state is `YoutubeLoaded`, emit a transient `YoutubeFailure` for the SnackBar, then immediately re-emit `lastLoaded` to preserve shelves.
  - In `_onYoutubeSyncProgressUpdated`, when `failed`: same behavior (failure then restore last loaded if available).
